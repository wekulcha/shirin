# Ширин

Приложение для заказов напитков «Ширин» и «Сады Востока» магазинами в Узбекистане: Telegram Mini App, административная панель, один aiogram-бот и отдельный backend/БД. Интерфейсы RU/UZ, расчёты только в UZS. Основа — KULCHA Market; исходные пути, коммиты и переиспользованные модули описаны в [аудите](docs/source-audit.md).

Реализация находится в `develop`; `main` содержит первоначальную основу и не объединён с `develop`. Интеграция общей суперадминки находится в соседнем worktree `../market-shirin-integration`, ветка `feature/shirin-integration`. Рабочие папки `../market` и `../kulcha` сохранены.

## Локальный запуск

Нужны Python 3.12+ и Node.js 22+. Проверенное локальное окружение: Python 3.14, PostgreSQL 18; контейнеры рассчитаны на Python 3.12/PostgreSQL 16.

```bash
cd /Users/amonulloh/Downloads/klch_project/shirin
make setup  # при первом запуске; здесь зависимости уже установлены
make dev
```

`make dev` выполняет миграции отдельной SQLite demo-БД, добавляет три синтетических товара и магазин, затем запускает backend на `8083`, Mini App на `5183`, админку на `5184`. В терминале появляются подписанные ссылки для входа: пользователь `101` — разработчик, `202` — существующее право работы с заказами, `303` — обычный пользователь. Ссылки действуют 10 минут; новые можно получить командой `make demo`. Ctrl+C останавливает процессы этого запуска.

Вход в demo проходит ту же HMAC-проверку initData, что и Telegram. Синтетический token и случайные локальные секреты создаются только в игнорируемой `.env`. Скрипт отказывается засевать production или чужую БД. Бот не подключается к Telegram, группа равна `0`, уведомления остаются в outbox. Персональные данные и токены исходных проектов не переносятся.

Отдельные процессы после `make demo`:

```bash
cd backend
../.venv/bin/uvicorn app.main:app --port 8083 --reload --no-access-log
# В других терминалах из корня shirin:
npm --prefix user_panel run dev
npm --prefix admin_panel run dev
```

Для настоящего тестового бота подготовьте отдельное окружение по [инструкции Telegram](docs/telegram.md). В нём из `backend` запускаются:

```bash
../.venv/bin/python -m app.bot
../.venv/bin/python -m app.services.notifications
```

## Реализованные сценарии

- Каталог двух брендов, поиск и фильтры; продажа бутылками, ящиками либо обоими форматами. Цена ящика независима от цены бутылки, размер упаковки индивидуален.
- Корзина, поиск доступных магазинов, ввод нового магазина, подтверждаемая точка на карте, необязательное закрытое фото. Итог пересчитывает backend; изменения после проверки требуют нового подтверждения.
- Заказы с номером `SH-…`, сохранёнными снимками товаров и магазина, защитой повторного оформления, историей, отдельной оплатой и автоматическим завершением после доставки и оплаты.
- Админка товаров/клиентов/заказов, фото, существующие два права сотрудников, Excel preview с изменениями, атомарным применением и журналом.
- Бот: административные кнопки/команды, Excel, выбор товара и подтверждение фотографии, проверки доступа и сохраняемые диалоги. Постоянный outbox повторяет уведомления после ошибок и перезапуска.
- Полноценное управление Shirin из суперадминки Market через подписанный backend proxy. Данные, токены, cookies и браузерное хранение проектов разделены.

FastAPI/SQLAlchemy/Asyncpg/Alembic и React/TypeScript/Vite/TanStack Query соответствуют исходной основе. Общие бизнес-сервисы используются API, ботом и интеграцией Market.

## Проверки

```bash
make test             # изолированная SQLite
make check            # Python Ruff, ESLint обеих панелей
make build            # TypeScript и production-сборки обеих панелей
cd user_panel
npx playwright test   # мобильные/административные сценарии demo
```

PostgreSQL-тесты удаляют и создают таблицы **только в выделенной тестовой БД**:

```bash
TEST_DATABASE_URL=postgresql+asyncpg://TEST_USER@127.0.0.1:5544/shirin_test .venv/bin/pytest -q
```

Полные результаты и ограничения — в [docs/test-results.md](docs/test-results.md). Тестовая интеграция с реальным кодом Market описана в [docs/market-integration.md](docs/market-integration.md).

