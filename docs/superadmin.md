# Отдельная суперадминка Shirin

Суперадминка собирается из `superadmin_panel` и обращается напрямую к `/shirin/api/` собственного backend. В ней доступны обзор заказов и неоплаченной суммы в UZS, каталог/фото, клиенты, Excel preview/apply, заказы/оплата/доставка, права сотрудников и настройки. Интерфейс поддерживает RU/UZ.

## Локальная проверка

```bash
cd /Users/amonulloh/Downloads/klch_project/shirin
make dev-superadmin
```

Команда запускает backend `8083` и суперадминку `5185`, применяет миграции demo-БД и печатает подписанную ссылку для синтетического суперадминистратора `101`. Открыть нужно всю ссылку с `#tgWebAppData`. Если она истекла, получить новую: `.venv/bin/python scripts/demo.py --links-only --superadmin`. Ctrl+C завершает процессы запуска. Для всех трёх панелей используйте `make dev`.

В demo используются отдельная SQLite-БД, синтетический token, товары и пользователи. Реальные сообщения не отправляются: группа равна `0`. Эти ссылки не подходят для production.

## Вход настоящего суперадминистратора

1. Настройте собственный бот Shirin и HTTPS по [telegram.md](telegram.md) и [deployment.md](deployment.md).
2. Добавьте нужные Telegram ID в `SHIRIN_SUPERADMIN_ALLOWED_IDS`, например `123456789,987654321`. Пустой список закрывает доступ всем. После изменения перезапустите backend и бот.
3. Укажите `SHIRIN_SUPERADMIN_APP_URL`; подготовленный адрес — `https://adminmarket.wekulcha.online/shirin/superadmin/`.
4. Отправьте `/start` боту Shirin. Разрешённый пользователь увидит отдельную кнопку «Суперадмин Shirin». Откройте её: backend проверит initData этого бота и выдаст собственную сессию Shirin.

Пароль и аккаунт Market для входа не используются. Backend проверяет allowlist при каждом запросе, включая `/superadmin/me`, `/superadmin/overview` и `/access`. Выдача обоих прав сотрудника не делает его суперадминистратором. Кнопка «Выйти» отзывает refresh-сессию и очищает токен, данные запросов и подписанный hash этой страницы.

## Права сотрудников

Остаются два существующих права: `CAN_EDIT_MENU` и `CAN_LOOK_ORDERS`. Раздел «Доступы» в суперадминке меняет только их. Пользователь должен сначала начать диалог с ботом или войти в Mini App Shirin, чтобы появиться в списке. Панель сотрудников `5184` отображает доступные по его правам разделы; управление правами находится в отдельной суперадминке.

## Удаление связи с Market

В Shirin удалены обработка подписанных запросов Market, интеграционные secrets, скрипты синхронизации/демонстрации Market и статус интеграции в настройках. Старые `X-Shirin-*` заголовки без сессии Shirin получают `401`. Миграция `7b425c210cc9` удаляет только служебную таблицу `integration_nonces`; товары, пользователи, права, клиенты и заказы сохраняются. Применение: из `backend` выполнить `../.venv/bin/alembic upgrade head` в выбранном окружении Shirin; Compose делает это автоматически через `migrate`.

В worktree `../market-shirin-integration` подготовлен обратный коммит интеграции `4552e9d`: удаляются proxy API, страница/кнопка Shirin, настройки и дополнения gateway. Итоговое дерево этой ветки соответствует основе `4bf905f`. История сохранена. Отправьте обратный коммит в её remote, если эта ветка уже опубликована. Если интеграция была отдельно объединена или размещена на сервере, обратный коммит нужно включить в соответствующую ветку и обновить сервер; локальная работа не выполняет production-развёртывание.

Пути на существующих доменах сохранены в примере Caddy. Общий gateway отвечает только за маршрутизацию HTTP и не передаёт учётные данные Market. Compose создаёт сеть Shirin `shirin_gateway`; постоянная зависимость от сети Market удалена.
