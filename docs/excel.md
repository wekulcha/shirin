# Каталог Excel / Excel katalogi

Админка: Excel → Скачать каталог / Скачать шаблон → Загрузить → проверить строки и изменения → Применить или Отмена. Бот использует те же сервисы и те же таблицы:

| Команда | Действие |
| --- | --- |
| `/export_meals` | Актуальный каталог |
| `/update_meals` | Каталог и ожидание изменений |
| `/add_meal` | Пустой шаблон и ожидание файла |
| `/remove_meal` | Поиск SKU/названия, выбор и подтверждение скрытия |
| `/set_photo` | Поиск/выбор товара, фото, preview и подтверждение |
| `/cancel` | Отмена диалога |

Диалог привязан к Telegram ID и выбранному товару. Ожидание — 30 минут. Кнопки доступны в меню бота; команды необязательно запоминать. Права `CAN_EDIT_MENU` проверяются снова при применении.

## Стабильный формат

Файл `.xlsx` имеет листы `Products` и `Instructions`. Заголовки Products в первой строке **не переименовывать**; русский и узбекский текст находится на Instructions. Колонки:

`sku, action, brand, category, name_ru, name_uz, description_ru, description_uz, volume_ml, sell_by_unit, sell_by_package, units_per_package, unit_price_uzs, package_price_uzs, is_active, photo_reference`.

- SKU — текст. Колонка шаблона имеет формат Text; сохраняйте его для ведущих нулей. Числовые SKU отклоняются с понятной ошибкой.
- `action`: `upsert` (по умолчанию) или `archive`. Новый SKU создаётся, существующий обновляется с сохранением ID. Изменять SKU существующего товара через обычное редактирование нельзя.
- `brand`: «Ширин» или «Сады Востока». `category` — текстовое название, не внутренний ID.
- Для нового SKU обязательны бренд, категория, `name_ru`, `name_uz`, хотя бы один способ продажи и цена включённого способа. Для ящиков обязательны целый положительный `units_per_package` и независимая `package_price_uzs`.
- Булевы значения: настоящие Excel boolean, `true/false` или `1/0`. Цены — числа ≥0 с максимум двумя знаками после точки, UZS. `volume_ml` — необязательное положительное целое.
- Пустая ячейка существующего SKU **сохраняет** значение. `0` и `false` обновляют его. `__CLEAR__` очищает descriptions/volume и параметры отключённого способа; обязательные поля очистить нельзя.
- `archive`/`is_active=false` скрывает товар. Отсутствующие SKU не меняются. Фото сохраняется всегда; `photo_reference` информационное и не загружает новые изображения.

Нет складского поля: исходный Market не ведёт количественные остатки. Параметры отключённого способа нормализуются в null; это не меняет старые снимки заказов. Размер ящика не считается остатком.

## Проверка и атомарное применение

Лимиты по умолчанию — 8 MB и 3000 строк. ZIP содержимое ограничено 40 MB/250 entries. Макросы, внешние подключения и небезопасный XML отклоняются; формулы в импортируемых колонках дают ошибку «вставьте значения». В экспортируемом Excel любой текст записывается как текст, включая названия, начинающиеся с `=`.

Preview содержит номера строк/колонок, добавления, изменения, скрытия, прежние/новые значения и предупреждение при изменении цены ≥20%. Ошибки запрещают применение. Preview хранится в БД и привязан к хэшу файла, пользователю, собственной базе проекта и сроку 30 минут. Повторная загрузка того же файла в пределах этого срока возвращает ту же проверку. При применении снова проверяются права и версии всех затронутых товаров. Конфликт требует новой проверки; пакет не перезаписывает более свежие изменения. Любая ошибка записи откатывает весь пакет. Повторное Применить возвращает прежний результат и не дублирует журнал или товары.

Журнал фиксирует actor ID, время и числа добавленных/изменённых/скрытых/неизменённых SKU. Экспорт → импорт проверен без смысловых изменений, включая ведущие нули, фото и текстовые названия с `=`. Для больших импортов бот разбивает полный отчёт на несколько сообщений; подробности также доступны в админке.

Faylni yuklab, xatolarni tuzating, o‘zgarishlarni tekshiring va «Qo‘llash» ni bosing. Suratlar Excel orqali yuklanmaydi.
