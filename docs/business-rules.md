# Правила проекта

## Товары и цены

Два допустимых бренда: «Ширин», «Сады Востока». SKU задаётся администратором и уникален; редактирование существующего товара не переименовывает SKU. Названия обязательны на RU и UZ, описания необязательны. Категория — название, без числового ID.

У товара включён хотя бы один формат. Для бутылки обязательна неотрицательная цена; для ящика — отдельная цена и целое положительное число бутылок. Выключенный формат не участвует в заказах, его цена/размер очищаются. Размер ящика не является остатком: исходный Market не содержит количественного склада, поэтому складская подсистема не добавлялась.

Количество позиции — положительное целое число, не более 100000. В заказе до 100 строк; два формата одного товара — разные строки. Цена хранится Decimal/Numeric с двумя знаками. Сервер считает `количество × цену выбранного формата`; ящик не пересчитывается из бутылок. Например, 2 ящика по 135000 UZS и 3 бутылки по 12000 UZS дают 306000 UZS и 27 базовых единиц при размере ящика 12.

Перед записью сервер формирует подписанное предложение на 10 минут, привязанное к пользователю, корзине и магазину. Изменённые цены/форматы или истечение срока требуют повторной проверки и подтверждения. Ключ попытки оформления уникален в пределах автора: повторная отправка возвращает тот же заказ, иной состав с тем же ключом отклоняется.

В заказ сохраняются названия RU/UZ, SKU, формат, размер упаковки, количество упаковок и базовых единиц, цена и сумма каждой строки. Последующие изменения каталога/фото не переписывают историю.

## Магазины и доступ

Для заказа обязательны название магазина, валидный телефон и адрес. Телефон из девяти цифр нормализуется как узбекский `+998…`; международные номера принимаются в формате `+…`. Дополнительные контакты, координаты, ссылка и фото необязательны. Координаты задаются парой, проверяются на диапазон и создают ссылку Яндекс Карт с порядком `долгота,широта`. Местоположение пользователя сначала показывается для подтверждения; адрес можно ввести вручную.

Checkout использует собственный черновик вкладки. Выбранный клиент заполняет поля, но изменения оформляемого заказа сохраняются в его снимке; карточка клиента не перезаписывается автоматически. Обычный пользователь может оформить новый магазин без записи в справочник. Сотрудник с правом каталога может создать клиента из заказа. Коды клиентов уникальны; отсутствие кода при создании справочника приводит к генерации кода.

Сохраняются два существующих права: `CAN_EDIT_MENU` для товаров, клиентов, Excel/фото; `CAN_LOOK_ORDERS` для всех заказов, доставки/оплаты. Пользователь без этих прав видит свои заказы и клиентов, которых создал либо использовал в собственных заказах. Фото магазина доступны соответствующему владельцу/пользователю или уполномоченному сотруднику. Привилегия разработчика задаётся явным allowlist Telegram IDs и позволяет выдавать эти права; новой третьей роли нет.

## Статусы и оплата

| Действие | Итог |
| --- | --- |
| Создание | Принят / Не оплачено |
| Готовность | Готов к доставке |
| Доставка без оплаты | Доставлен / Не оплачено |
| Оплата до доставки | Текущий статус / Оплачено |
| Доставка и оплата отмечены | Завершён / Оплачено |

Переходы идут последовательно: ACCEPTED → READY → DELIVERED. COMPLETED устанавливается общей логикой, когда есть оба факта. Нельзя вручную завершить неоплаченный/недоставленный заказ. Частичных платежей, возвратов и эквайринга нет. Автор заказа без права работы с заказами не подтверждает оплату/доставку.

Изменения сохраняют автора, время UTC, значения до/после. Повторный переход не создаёт нового события или уведомления. Номер `SH-000123` вычисляется из стабильного ID. База хранит UTC, UI и группа показывают настраиваемую Asia/Tashkent.

## Уведомления

Заказ, первое событие и outbox создаются одной транзакцией. Worker забирает задание с арендой, сохраняет ID каждой отправленной части, повторяет после ошибки/перезапуска с задержкой и учитывает Telegram retry_after. Изменение статуса создаёт связанное уведомление «Обновление заказа».

Сообщения отправляются обычным текстом без интерпретации пользовательской разметки. Длинный заказ разбивается по длине UTF-16; фото отправляется отдельно с короткой подписью, полный состав остаётся в текстовых частях. Есть кнопки заказа/карты/доступных переходов. Права проверяются в callback по текущей БД, участие в группе само по себе их не даёт.

Семантика доставки — at least once: при неоднозначном сетевом timeout после принятия сообщения Telegram возможна повторная часть. У Bot API нет ключа идемпотентности отправки. Уже подтверждённые message IDs сохраняются и не отправляются повторно; заказ никогда не требуется оформлять заново из-за Telegram.
