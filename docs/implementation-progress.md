# Ход реализации

Все доступные локальные этапы выполнены 3 октября 2026. Рабочая реализация в `develop`; `main` не изменён после первоначальной основы.

| Этап | Результат и проверка |
| --- | --- |
| 1. Аудит/репозиторий | Найдены оба исходных корня/коммита, выяснены реальные два права и архитектура; отдельная `.git`, main/develop и изолированная ветка Market. Исходные рабочие папки чистые. |
| 2. Изоляция/миграции | Собственные SHIRIN_ secrets/БД/бот, scoped cookie/storage, RU/UZ, Decimal UZS. Две миграции применены к пустой PostgreSQL, `alembic check` без расхождений. |
| 3. Каталог/фото | Два бренда и три сочетания форматов, независимые цены, версия товара, immutable SKU, реальные JPEG/PNG/WEBP с нормализацией, private media и placeholder. API/ботовые тесты, обе панели собираются. |
| 4. Магазины/checkout | Справочник с доступами, снимок нового магазина, optional photo, Yandex URL, Telegram LocationManager/fallback и явное подтверждение точки. Мобильный браузер подтвердил свой черновик каждой вкладки. |
| 5. Заказы | Серверное предложение, точные суммы/снимки, идемпотентность включая PostgreSQL race, статусы/оплата/события. Оба порядка оплаты/доставки проверены. |
| 6. Бот/outbox | Один aiogram бот, durable диалоги, выбор/preview/подтверждение фото, RUUZ, persistent leased outbox, retry/части/message IDs. Fake transport/handlers, ошибки/рестарт/истечение состояния проверены. |
| 7. Excel | Безопасный .xlsx Products/Instructions, preview diff, ошибки/предупреждения, 0/false/clear, версии/права/срок, атомарность/лог и повторное применение. Roundtrip и инъекция ошибки записи проходят. |
| 8. Market/routes | Настоящие CRUD, клиенты/заказы/доступы/Excel в существующей панели через подписанный proxy. Две отдельные БД. HTTP smoke, браузер и Caddy подтвердили интеграцию и прежние корневые маршруты. |
| 9. Проверки/docs/review | 23 PostgreSQL tests, 22 SQLite + 1 skip, 4 browser tests; Ruff/ESLint/TS/build и Caddy/Compose validation проходят. Документация запуска/Telegram/Excel/deployment/правил/интеграции/результатов готова. |

PostgreSQL проверка обнаружила несовместимое `FOR UPDATE` с nullable joined User в унаследованной refresh-модели. Блокировка ограничена RefreshSession; последующая полная проверка проходит. HTTP smoke выявил необходимость сохранять исходное multipart тело до обработки FastAPI; подпись теперь проверяется по этим байтам.

Точное разграничение проверенных и внешних этапов — `test-results.md`. Реальный Telegram, S3, контейнерные images и HTTPS production не проверены без соответствующих ключей/служб. Никакие production миграции, переключения ботов, отправки в рабочую группу или публикации не выполнены. Git remote требует создания приватного `shirin` и подключения по инструкции README.
